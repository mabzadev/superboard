# OpenGrow implementation and readiness audit — updated 10 August 2026

This is the hand-off record for the `opengrow-platform` and `opengrow-reference`
baseline. It distinguishes code that exists and has been validated locally from
operations that still require an external account, secret, provisioned resource
or destructive cutover approval.

## Executive result

The reusable architecture is implemented locally and behaves as one
manifest-driven Cloudflare control plane. It contains the complete MBZA
development target, the VocoStar production convergence target, sixteen Worker
deployment roles, a dashboard, seven SDK catalog entries, a canonical
FlutterFlow code catalogue and an executable sixteen-journey reference app with
an independent Static Assets deployment contract for `reference.mbza.dev`.

The MBZA control plane is now **provisioned and deployed privately** in the
intended Cloudflare development account. All sixteen Worker roles have one
active version at 100%, all twelve D1 schemas are converged through the deployed
baseline, every required secret name is present, and the declared KV, R2,
Queue, Durable Object and Analytics bindings exist. The newly tracked OAuth
overlap migration 0056, Marketing application-preference migration 0009 and
Reference Custom acceptance-receipt migration 0002 remain intentionally
pending until the Git release.
Public custom domains remain deliberately detached:
the DNS ownership gate cannot inspect records with the current short-lived
OAuth grant and `in.mbza.dev` is known to have an externally managed record.

The two configured GitHub repositories exist publicly under the authenticated
`mbzadev` user. Their reviewed histories are pushed to `dev`, both `dev` and
`main` are protected, the declared GitHub Environments and non-secret variables
are reconciled, and all repository settings match the versioned control-plane
manifest. Protected CI has published Flutter `2.1.3`, FlutterFlow `2.2.4`,
Support `1.3.0`, iOS `1.0.2` and Android `1.0.2`;
`opengrow-reference/dev` now pins the two FlutterFlow packages to their
immutable released tags. The remaining GitHub gates are encrypted Environment
secrets and the JavaScript and React
Native `1.0.1` package publications. No VocoStar production migration, DNS
cutover, Chatwoot removal or legacy resource deletion was performed.

VocoStar now explicitly uses `publicRouting: staged`. Generated production
Workers have no custom-domain routes, while MBZA development remains `active`.
Target schema version 8 and the deployment workflow reject production
activation unless `productionCutover` references a valid snapshot-bound
FlutterFlow client receipt. The live routing mode is exposed by
`/api/v1/platform/status` and the Infrastructure page.

## Final baseline hardening

The last local pass completed the public, reusable repository boundary:

- both repositories carry the same root MIT licence plus root contribution and
  private security-reporting policies; SDK release and native package metadata
  consistently describe the public OpenGrow source and GitHub Packages target;
- public platform checkout requires no repository read token anywhere in the
  reference workflow or documentation;
- reference URLs and GitHub repositories in readiness checks and the
  cross-repository acceptance workflow are derived from target/project and
  control-plane manifests, not from MBZA or `mbzadev` workflow constants;
- governance and target schema identifiers are neutral, while the current
  owner/repository values remain explicit versioned configuration;
- deployment validates the current target's custom Worker dynamically, and CI
  discovers every unique `customWorker.packagePath` declared by all targets;
- custom extension `Env` declarations are now generated by Wrangler from the
  owning target's variables, D1 and Service Bindings, with declared secret
  names appended by the generator; handwritten custom binding contracts were
  removed and stale generated types fail CI;
- the full 31-Worker target/environment matrix is schema-checked against
  Wrangler 4.120.0 and policy-checked for current compatibility dates,
  `nodejs_compat`, disabled preview surfaces, structured logs/traces and
  isolated preflight versions without routes, crons or Queue consumers;
- all production Worker provider responses are streamed through byte-bounded
  readers before parsing. Source policy rejects unbounded response buffering,
  `Math.random`, `passThroughOnException`, destructured `waitUntil` and new
  Cloudflare REST callers outside the Analytics Engine SQL read authority;
- Observability and custom-Worker status contracts are byte-bounded and
  structurally validated before the back-office consumes them. Central D1
  metric or persisted-job query failure now degrades the platform instead of
  producing a false healthy status. Healthy service responses with absent or
  malformed job metrics remain unavailable rather than becoming invented zero
  counters. Every D1-owning generated Worker config pins `d1_migrations` and
  derives `D1_EXPECTED_MIGRATION` from its actual reviewed Git chain. Runtime
  health exposes `current`, `behind` or `drifted`, expected/latest migration and
  applied count; a service response that says `ok` without a valid current
  schema still degrades its datastore and the aggregate platform. Public
  monitors reject malformed, private-address, credentialed,
  cross-origin or excessive probe definitions, and custom operator responses
  have a two-megabyte bound. The Infrastructure page has direct tests for
  endpoints, Worker purposes, stores, runtime metrics and custom-job retry. It
  displays the active API status, description, target, environment and release
  beside its capability catalogue. Every capability also declares and displays
  its access model and public/administrative entrypoint groups rather than
  leaving those operational fields only in source or the operator JSON response;
- Cloudflare resource bootstrap is now remote-inventory aware, fully paginated,
  drift blocking and account-bound to a plan-specific confirmation. Existing
  exact-name resources are adopted explicitly, while configured ID/name drift
  prevents every creation; no bootstrap path deletes or replaces a resource;
- full production rollout now exports every enabled D1 before the first
  migration, migrates and verifies the complete database set, writes a
  target/environment-scoped batch receipt, and only then enters the Worker
  deployment loop. Successful retention validates every SQL export and
  per-database receipt against that batch. Empty encryption is rejected;
  recoverable encrypted evidence is uploaded even after rollout failure;
- a read-only Git history plan verifies canonical remotes, local branches,
  cleanliness, exact remote SHAs and merge bases for both repositories. It
  detects the independently initialized `main` histories and emits audit-ref
  preservation before `dev` publication without itself committing or pushing.
  Occupied audit refs and non-fast-forward remote `dev` histories block rather
  than suggesting a force-push;
- the lockfile uses the retrieved current Cloudflare Workers types
  `5.20260809.1`; compatible Flutter transitive storage/StoreKit/Win32 patches
  were resolved without widening public SDK constraints. npm audits remain at
  zero vulnerabilities and incompatible major upgrades remain isolated for
  reviewed release work;
- GitHub Actions is the only automatic Cloudflare deployment authority. The
  unused Workers Builds connector and command were removed to prevent competing
  migrations, routes or Queue consumers;
- file upload limits and exact/wildcard MIME allowlists now belong to target
  schema v8 rather than a reusable-source constant. Files validates the policy
  at health time and rejects disallowed media before writing R2. Target
  registration requires a reviewed remote bootstrap confirmation and never
  deploys before secrets are configured;
- post-bootstrap Google/Apple audiences, HTTPS origins and numeric Support
  project IDs now use one target-generic plan/apply command. Its exact
  confirmation is derived from the desired public values, apply is atomic and
  schema-validated, explicit clear operations cannot be confused with missing
  arguments, and the command never accepts a credential value. Readiness links
  each missing MBZA registration directly to the corresponding command;
- the fake unauthenticated notification diagnostic was removed. The remaining
  surface is the real authenticated project/SDK/push contract. APNs and FCM
  credentials, including cached FCM OAuth tokens and preserved unsupported
  legacy RPush material, are encrypted in D1 with the existing versioned
  keyring. Migration 0054 plus bounded maintenance converges plaintext rows;
  provider calls are time-bounded and conditional 15-minute claims recover
  abandoned jobs while preventing concurrent double delivery. Infrastructure
  status exposes push devices, notification/message totals, delivery states and
  credential security, and degrades on plaintext or missing credentials;
- reusable authentication material no longer survives new D1 writes in clear:
  Dashboard OAuth and MCP bearer pairs, OAuth client secrets, invitations and
  password resets are SHA-256 digests; TOTP seeds are encrypted because they
  must be read for verification. Authentication keeps bounded legacy lookup
  compatibility while maintenance converges old rows. OAuth rotation writes a
  digest to D1 and only uploads the clear client secret to the Dashboard Worker.
  Infrastructure exposes bearer/TOTP storage state and degrades until reusable
  plaintext reaches zero. Migration 0056 adds one previous verifier with a
  bounded lifetime: rotation first uploads an inactive Dashboard version,
  moves the current hash into that slot, activates the exact tagged version and
  restores the previous hash if activation fails;
- the schema-2 secret inventory now proves complete ownership of every required
  binding and groups shared values into target/environment-isolated contracts.
  The old single-binding command is a non-mutating compatibility guard. The
  coordinated uploader accepts an exact JSON bundle from the secret manager,
  expands each shared contract in memory, creates uniquely tagged inactive
  Worker versions and emits a value-free receipt. Promotion rechecks every tag,
  binds the plan to the Cloudflare account and exact active rollback versions,
  deploys current-plus-previous consumers before new-token-only producers and
  restores already changed Workers in reverse order after failure. A separate
  account- and exact-version-bound retirement enforces at least thirty minutes
  of observation, removes only optional `*_PREVIOUS` bindings and also rolls
  back on failure. Shared contracts without overlap remain blocked unless a
  bootstrap or maintenance cutover is explicitly accepted. Generated
  Wrangler configurations also declare `secrets.required`, so Cloudflare's
  native upload gate and OpenGrow's remote name-only preflight enforce the same
  target contract;
- central Dashboard password/OAuth login, registration, invitation and reset
  paths now share a D1 ten-minute rate-limit authority keyed only by a SHA-256
  digest of scope, Cloudflare client IP and subject. It emits no-store 429
  responses with `Retry-After`, exposes active blocks to Infrastructure and
  purges expired counters during maintenance. Public API readiness now checks
  central D1, KV and mandatory domain configuration instead of returning an
  unconditional `ok`; provider and service calls gained bounded timeouts;
- the prepared indexes currently contain 962 platform paths and 35 reference
  paths. The subsequent hardening adds 144 tracked and 21 untracked platform
  paths plus 17 tracked and 2 untracked reference paths; these remain unstaged
  pending the separately authorized Git publication sequence. The resulting
  unique working sets are 985 platform paths and 37 reference paths.
  `git diff --check` reports no whitespace error and the current-tree plus
  history Gitleaks scans cover both repositories without finding a disclosure;
- the canonical FlutterFlow catalogue now covers every public symbol and every
  Dart source file from both reusable packages: 5 widgets, 89 actions, 4 event
  streams and 16 source files. The Dashboard links each library and source file
  to the Git development branch while immutable tags remain the only
  production install authority. CI rejects missing, duplicated or stale public
  declarations;
- the VocoStar migration is now a strict machine-readable contract rather than
  only a narrative checklist. Seven ordered dependency phases contain ten work
  items that cover all 25 authenticated source gates exactly once and reference
  34 distinct symbols proven in the public FlutterFlow catalogue. The same
  joined plan is returned by global readiness with blocked work items,
  replacement symbols and acceptance criteria;
- checked-in Wrangler templates no longer contain the two observed MBZA D1
  identifiers. A source-policy test now permits only explicit zero UUID
  placeholders in reusable Worker templates; real D1/KV/account/zone IDs may
  exist only in generated target output or target manifests.
